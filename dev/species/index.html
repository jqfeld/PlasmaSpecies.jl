Species and states

A Species is one state of one gas: a Gas, a Charge, and optionally an electronic, vibrational and rotational state.

PlasmaSpecies.Species — Type
Species(; gas, charge=Neutral(), electronic_state=nothing,
          vibrational_state=nothing, rotational_state=nothing,
          energy=nothing, degeneracy=nothing, metadata=nothing)

One state of one gas. All fields are type parameters, so a Species is concretely typed and cheap to store in arrays and Dict keys.

Usually built from a LoKI-B string instead — see Species(::String).

Identity fields

Compared by == and hashed. Together they name the state:

  • gas: the parent gas. Normally a Molecule resolved from a chemical formula (see parse_formula), otherwise Electron or the StringGas fallback.
  • charge: Neutral (default), Positive(n) or Negative(n).
  • electronic_state: an ElectronicState, or nothing for unresolved.
  • vibrational_state, rotational_state: a QuantumLabel, or nothing. By convention a resolved level implies its parent is resolved too (rot without vib is meaningless), but this is not enforced.

nothing means unresolved, not zero: N2 is bulk N₂, N2[X,vib=0] is its ground vibrational level, and the two are different species that a SpeciesTree relates as parent and child.

Payload fields

Ignored by == and hash, carried through with_fields:

  • energy: level energy, used by reaction_energy. Set in bulk with apply_energy!.
  • degeneracy: statistical weight of the level.
  • metadata: opaque payload for downstream packages.

The split is deliberate: energy/degeneracy/metadata are annotations on a state, not part of its identity, so attaching them never breaks a Dict{Species,V} lookup.

An Electron gas always carries Negative(1); any charge passed for one is normalised to that.

The string notation

Species are normally written as strings, in the notation of the LoKI-B Boltzmann solver:

GAS[CHARGE,ELECTRONIC,vib=VIB,rot=ROT]

Every bracketed field is optional, but the order is fixed.

FieldSyntaxBecomes
GASN2, CO2, 16O-1H, ea Gas — see Gases and masses
CHARGE+, ++, -, 0, omittedPositive, Negative, Neutral
ELECTRONICX, a'', B3Pigan ElectronicState
vib=, rot=0, 0-4, (0,1,0), (v1=1,v2=0), asyma QuantumLabel
julia> using PlasmaSpecies
julia> Species("e")e
julia> Species("N2[+]")N2[+]
julia> Species("N2[+,B]")N2[+,B]
julia> Species("N2[X,vib=0,rot=10]")N2[X,vib=0,rot=10]
julia> p"N4[+]"N4[+]

The p"..." macro parses a species or a reaction, whichever the string looks like. Whitespace is stripped, and a + inside brackets is never mistaken for a charge separator.

A malformed string throws rather than parsing the part it recognises — "N2[+" is a typo, not a neutral N₂.

julia> Species("N2[+")ERROR: Cannot parse species string "N2[+". Expected GAS[(CHARGE,ELECTRONIC_STATE,vib=VSTATE,rot=JSTATE)], e.g. "N2[+,B,vib=3,rot=1]".

Quantum labels

vib=/rot= accept more than a single quantum number. The forms are collected in QuantumLabel and parsed by parse_quantum_label:

julia> vibrational_state(Species("N2[X,vib=3]"))          # one level3
julia> vibrational_state(Species("N2[X,vib=0-4]"))        # a lumped range0:4
julia> vibrational_state(Species("CO2[X,vib=(0,1,0)]"))   # normal modes(0, 1, 0)
julia> vibrational_state(Species("CO2[X,vib=(v1=1,v2=0)]"))(v1 = 1, v2 = 0)
julia> vibrational_state(Species("N2[X,vib=asym]"))       # opaque label:asym

A range is the one form with containment semantics: vib=0-4 matches the levels inside it when a reaction is expanded over a tree. A Symbol label is deliberately opaque and only ever matches itself.

Display round-trips: Species(string(sp)) == sp for every form above.

Electronic states

A plain letter label becomes a StringElectronicState. A fused term-symbol string, in the spelling ExoMol's ElecState column uses, decomposes into a TermSymbol:

julia> electronic_state(Species("N2[+,B]"))B
julia> ts = ElectronicState("A3Sigmau+")A
julia> ts.multiplicity, ts.Λ, ts.parity, ts.reflection(3, 0, :u, :plus)

Both compare by label alone, so a TermSymbol and a bare label for the same state are equal and interchangeable when matching. The extra physics is annotation.

Fields and accessors

julia> sp = Species("N2[+,B]")N2[+,B]
julia> gas(sp)N₂
julia> charge(sp)+
julia> electronic_state(sp)B
julia> vibrational_state(sp) === nothingtrue

nothing means unresolved, not zero. N2 is bulk N₂ and N2[X,vib=0] is its ground vibrational level; they are different species, related by a SpeciesTree.

Three further fields carry data about a state rather than naming it: energy, degeneracy and metadata. Set them with with_fields, which copies a species and replaces only the named fields:

julia> excited = with_fields(sp, energy = 11.03, degeneracy = 3)N2[+,B]
julia> energy(excited), degeneracy(excited)(11.03, 3)

Species are immutable, so this is the only way to change one.

Identity

== and hash use the identity fields only — gas, charge, and the three state fields. energy, degeneracy and metadata are ignored:

julia> sp == excitedtrue
julia> hash(sp) == hash(excited)true
julia> d = Dict(sp => "N2+ in B"); d[excited]"N2+ in B"

That is deliberate. Attaching an energy or a downstream payload must not break a Dict{Species,V} lookup, which is how consumers index their state vectors.

Species also sort (isless is defined for them): electrons last, then by charge, gas, electronic state (with X first), and level. Sorting is total and never throws, even for mixed label types.

Matching states

Matching is separate from equality: a species with nothing or a range in a field acts as a pattern for the more resolved states under it.

PlasmaSpecies.level_matches — Function
level_matches(formula_value, candidate_value) -> Bool

Whether a single field (electronic/vibrational/rotational state) of a formula Species matches a concrete candidate value. nothing on the formula side is a wildcard (matches anything, as used by is_parent_species for hierarchy matching); a UnitRange{Int} on the formula side matches any Int it contains (used by matching_leaves to expand reactions written over a range of vibrational levels); everything else falls back to exact equality — including Symbol labels, which are deliberately opaque (no containment).

source
PlasmaSpecies.species_matches — Function
species_matches(formula::Species, candidate::Species) -> Bool

Whether candidate is matched by formula: gas/charge compared exactly, electronic/vibrational/rotational state compared via level_matches (so nothing/range fields on formula act as wildcards/containment checks). Used by matching_leaves to expand a reaction formula species — which may specify a range of vibrational levels — into every matching leaf of a SpeciesTree.

source
Base.in — Function
candidate::Species in formula::Species -> Bool

Whether candidate is matched by formula — an alias for species_matches(formula, candidate), exposed via ∈/in to mirror SpectraUtils's Base.in(child::State, parent::State) (e.g. s in boltzmann.parent). nothing/range fields on formula act as wildcards/ containment checks, same as species_matches; reflexive (sp in sp is true), unlike is_parent_species which is a strict-ancestor check and doesn't compare rotational_state.

source
PlasmaSpecies.is_parent_species — Function
is_parent_species(sp::Species, parent::Species) -> Bool

Whether parent is a strict ancestor of sp in the species hierarchy: same gas and charge, electronic and vibrational state matched via level_matches (so nothing on parent acts as a wildcard), and parent != sp. rotational_state is deliberately not compared. Unlike species_matches, this is irreflexive — a species is not its own parent.

source
julia> Species("N2[X,vib=1]") in Species("N2[X]")        # wildcard fieldtrue
julia> Species("N2[X,vib=2]") in Species("N2[X,vib=0-4]") # range contains leveltrue
julia> Species("N2[X]") in Species("N2[X]")               # reflexivetrue
julia> is_parent_species(Species("N2[X]"), Species("N2[X]"))  # strict: not its own parentfalse

Use in/species_matches to ask "does this pattern cover that state", and is_parent_species for hierarchy construction, where a species must not be its own ancestor. get_parent_species walks one step up:

julia> get_parent_species(Species("N2[X,vib=1]"))N2[X]
julia> get_parent_species(Species("N2"))

Mass

mass returns kg, derived from the gas composition, with the electrons implied by the charge added or removed:

julia> mass(p"N2")4.65183414117324e-26
julia> mass(p"N2[+]") == mass(p"N2") - mass(p"e")true
julia> mass(p"e")9.1093837015e-31

Any formula built from the nuclide tables works — no registration step. A label that is not a resolvable formula still parses and round-trips, but has no mass:

julia> gas(Species("Xyz"))Xyz
julia> mass(Species("Xyz"))ERROR: No mass available for Xyz: its label does not resolve to a chemical formula.
Check the spelling (symbols are case-sensitive, so `Co` is cobalt and `CO` is
carbon monoxide), or add the missing nuclide to `ISOTOPE_MASSES` in
src/nuclide_data.jl.

See Gases and masses for formula syntax, isotopes and the data tables.
