Species trees

A SpeciesTree holds the parent/child hierarchy of species: each child is a more resolved state of its parent, obtained by filling in one more field. Bulk N2 has the child N2[X], which has the children N2[X,vib=0], N2[X,vib=1], and so on.

The tree exists so that a chemistry can be written at one level of detail and solved at another. Reactions are written over whatever species the data source names — often lumped, e + N2[X] --> ... — while the model integrates the leaves. apply_tree bridges the two.

Building

Constructing from a species inserts its whole ancestor chain, found by repeated get_parent_species. Constructing from several merges those chains, sharing every common ancestor. The root is a node holding nothing.

julia> using PlasmaSpecies
julia> t = SpeciesTree(["e", "N2[X,vib=0]", "N2[X,vib=1]", "N2[X,vib=2]", "N2[+]"])nothing
├─ e
├─ N2
│  └─ N2[X]
│     ├─ N2[X,vib=0]
│     ├─ N2[X,vib=1]
│     └─ N2[X,vib=2]
└─ N2[+]

Accepted arguments: a Species or String, a vector of either, or varargs. Add to an existing tree with push!, or combine two with merge!:

julia> push!(t, "N2[X,vib=3]")nothing
├─ e
├─ N2
│  └─ N2[X]
│     ├─ N2[X,vib=0]
│     ├─ N2[X,vib=1]
│     ├─ N2[X,vib=2]
│     └─ N2[X,vib=3]
└─ N2[+]

t[sp] = subtree grafts a separately built branch onto an existing tree, replacing the node for sp value and children alike.

Querying

julia> leaves(t)6-element Vector{Species{S, C, E, V, Nothing, Nothing, Nothing, Nothing} where {S, C<:Charge, E, V}}:
 e
 N2[X,vib=0]
 N2[X,vib=1]
 N2[X,vib=2]
 N2[X,vib=3]
 N2[+]
julia> t["N2[X]"]N2[X]
├─ N2[X,vib=0]
├─ N2[X,vib=1]
├─ N2[X,vib=2]
└─ N2[X,vib=3]
julia> matching_leaves(t, Species("N2[X,vib=0-1]"))2-element Vector{Species}:
 N2[X,vib=0]
 N2[X,vib=1]
julia> matching_leaves(t, Species("O2"))Species[]

leaves gives the most resolved states — the model's unknowns. Indexing finds one node and returns its subtree, stopping at the first match. matching_leaves is the pattern query: it descends every branch and collects the leaves under each node that the given species matches, so a wildcard field or a vib=0-4 range expands to every level actually present.

The tree implements AbstractTrees, so print_tree, Leaves and the rest of that interface work directly on it.

Energies

apply_energy! fills the energy field of every leaf from a function of its state labels:

julia> tv = SpeciesTree(["N2[X,vib=0]", "N2[X,vib=1]", "N2[X,vib=2]"])nothing
└─ N2
   └─ N2[X]
      ├─ N2[X,vib=0]
      ├─ N2[X,vib=1]
      └─ N2[X,vib=2]
julia> apply_energy!(tv, q -> 0.29 * q.vib)   # eV, harmonicnothing
└─ N2
   └─ N2[X]
      ├─ N2[X,vib=0]
      ├─ N2[X,vib=1]
      └─ N2[X,vib=2]
julia> energy.(leaves(tv))3-element Vector{Float64}:
 0.0
 0.29
 0.58

The callback receives a named tuple (elec, vib, rot); the unit is the caller's choice, and only reaction_energy and thermal_source_term consume it. Leaves are rebuilt with with_fields, so every other field survives.

PlasmaSpecies.SpeciesTree — Type
SpeciesTree(sp::Species)
SpeciesTree(str::String)
SpeciesTree(species)          # Vector or varargs of Species / String

The species hierarchy: a node holds one Species (or nothing for the root) and its children, each a more resolved state of its parent.

Building from a species inserts its whole ancestor chain, obtained by repeated get_parent_species, so "N2[X,vib=1]" alone yields nothing → N2 → N2[X] → N2[X,vib=1]. Building from several species merges those chains, sharing every common ancestor.

julia> SpeciesTree(["e", "N2[X,vib=0]", "N2[X,vib=1]", "N2[+]"])
nothing
├─ e
├─ N2
│  └─ N2[X]
│     ├─ N2[X,vib=0]
│     └─ N2[X,vib=1]
└─ N2[+]

The tree implements AbstractTrees, so print_tree, Leaves and friends work on it. Supported operations: push! and merge! to add species, t[sp] / t["N2[X]"] to fetch a subtree (nothing if absent), t[sp] = subtree to replace one, leaves and matching_leaves to collect states, and apply_energy! to fill in level energies.

The leaves are the states a model actually integrates; interior nodes are the lumped species reactions may be written over. apply_tree uses that to expand a reaction written for N2[X] into one per vibrational level.

source
PlasmaSpecies.leaves — Function
leaves(t::SpeciesTree) -> Vector{Species}

Every leaf species of t, in tree order. These are the most resolved states in the hierarchy — the ones a model carries as unknowns.

source
PlasmaSpecies.matching_leaves — Function
matching_leaves(t::SpeciesTree, formula::Species) -> Vector{Species}

Collect every leaf of t matched by formula (via nodevalue(c) in formula, see Base.in/species_matches), descending into every branch rather than stopping at the first match like t[formula]/Base.getindex does. Whenever formula matches a node — exactly, or via a UnitRange vibrational/rotational field containing that node's level — the whole subtree's leaves are taken and that branch is not searched further; otherwise the search continues into the node's children. This is what lets a reaction formula species written with a vibrational range (e.g. vib=0-4) expand, in apply_tree, to every matching level actually present in the tree, even when those levels are separate sibling nodes.

source
PlasmaSpecies.apply_energy! — Function
apply_energy!(t::SpeciesTree, energy) -> SpeciesTree

Set the energy field of every leaf of t in place. energy is called with a named tuple (elec, vib, rot) of that leaf's state labels and returns its level energy; the unit is the caller's choice.

apply_energy!(t, q -> ωe * (q.vib + 0.5) - ωeχe * (q.vib + 0.5)^2)

Leaves are replaced via with_fields, so every other field survives. Interior nodes are left alone. reaction_energy consumes what this sets.

source

push!, merge!, getindex and setindex! are extended for SpeciesTree as described above; their docstrings are available at the REPL.
